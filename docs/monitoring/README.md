## 監視についての考え方（このドキュメント群の前提）

想定と違う事態（サービスが止まる、DB の情報を盗まれる）は、**前提が崩れたとき**に起こる。
前提は日々変わるので、それに追いつき続けることが大事である。

きっかけは [INC-001](../incidents/INC-001-ubuntu26-venv-broken.md)。
OS 更新で Python のパスが変わり、venv が壊れて 502 になった。
「`.venv/bin/python3` の実体がある」という前提は誰も見ていなかったし、
「OS のバージョンが変わった」という前提の変化も、壊れるまで誰も気づかなかった。

そこでこの監視設計では、CPU やメモリといった「量」だけでなく、
**「前提が今も成り立っているか」「前提が変わったか」** を見る項目を独立したカテゴリとして持つ
（[monitoring-design.md](monitoring-design.md) の「C. 前提の崩れ」）。
